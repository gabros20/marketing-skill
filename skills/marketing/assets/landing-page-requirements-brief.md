# Landing Page Requirements Brief

This is marketing's artifact and the whole of marketing's contribution to a page. **Composition is
design's** — the section order follows design's surface-website product-narrative question chain
(the 8 beats), which stays canonical there. Fill this in; hand it over; do not lay out the page.
Source: [`references/landing-pages-and-conversion.md`](../references/landing-pages-and-conversion.md).

## Page identity

| Field | Value |
|---|---|
| Page URL / working name | |
| Segment(s) this page must convert | |
| **The one goal** — the single action this page exists to produce | |
| Page mode | **Campaign** (Attention Ratio → 1:1, one action, nothing else clickable) / **Homepage** (1:many, exploration is the job) |
| Inbound promise — the exact ad, email subject, or post claim that sent them here | |

Conflating campaign and homepage mode is the most common briefing error. State which one this is.

## Message-match check

| The inbound promise says | The headline claim will say | Match? |
|---|---|---|
| | | |

Mirror the inbound promise's **specific language**, not just its general topic. A discount-led ad
landing on a page that never mentions the discount spends the visitor's trust before the page argues
anything. Imagery, palette and framing must carry through too — design executes it, marketing
requires it.

## Claims and proof

One row per claim the page must make. **A claim with no proof source is not a finished row** —
get the proof or drop the claim. "Trust us" is not a requirements line design can build against.

| Claim | Proof device | Where it must sit | Proof source (named, real) |
|---|---|---|---|
| | | | |
| | | | |

Proof devices, strongest first for high-consideration buys: **case study** (challenge → approach →
measurable result, named client) · **testimonial** (real quote, full name, role, company, headshot —
an initial like "Alex H." reads as fabricated) · **numbers** (specific beats superlative: "500+
transactions", not "trusted by many") · **logo wall** (recognisable logos beat a generic "trusted by"
bar) · **trust badges** (SOC 2, HIPAA, GDPR — function and signal).

**Placement is the lever, not presence.** Put the strongest testimonial, rating, or guarantee
directly beside the CTA or form. A fabricated or stock-photo testimonial is both easy to detect and
FTC-actionable — never brief one.

## Pricing pages only

`product` owns the price, the tier structure, and the decoy tier. Brief the **message** against tiers
already fixed: which tier's story leads · where the anchor sits (higher tier shown first sets the
frame) · which proof sits beside which tier, matched to that buyer · objection copy (refund terms,
"no credit card required", comparison table) at the point of hesitation. **Do not propose tier
changes inside this brief.**

## Ethics gate — run before handoff

For every persuasion mechanism used, confirm the claim underneath it is **true**:

- [ ] Scarcity/urgency → a real deadline or real stock level, never a re-arming timer
- [ ] Commitment → honest progressive disclosure, no cost hidden until a late step
- [ ] Social proof → real reviews under real identities
- [ ] Default/progress → true progress state, no forced continuity
- [ ] Endowment → easy sign-up matched by easy cancellation
- [ ] Opt-out copy is neutral, not confirmshaming

The mechanism is fine; verify the claim underneath it. Honest persuasion reduces friction to a
decision the visitor already wants to make.

## Handoff

- [ ] Every claim carries a proof source and a placement
- [ ] The page mode and Attention Ratio are stated explicitly
- [ ] Headline claim mirrors the inbound promise
- [ ] Nothing in this brief specifies layout, spacing, or visual hierarchy → that is design's
- [ ] Variant testing, if wanted, is routed to `growth` — not decided here
